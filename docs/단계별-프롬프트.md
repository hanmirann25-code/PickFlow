# PickFlow — 단계별 프롬프트 모음

커서 / 클로드 코드에 그대로 붙여넣어 쓰는 프롬프트집.
`docs/기획서.md`와 `AGENTS.md`가 저장소에 있다는 전제로 작성됐다.

---

## 쓰는 법

**6단계 · 프롬프트 27개로 구성돼 있다.** 기한은 없다. 한 단계를 제대로 끝내고 다음으로 가는 것이 순서를 지키는 것보다 중요하다. 다만 **1단계만은 반드시 먼저** 끝내야 한다.

**1. 한 번에 하나씩.** 프롬프트 두 개를 붙여 넣으면 앞엣것이 대충 처리된다.

**2. 각 단계의 "확인" 항목을 직접 통과시킨 뒤 다음으로.** AI가 "완료했습니다"라고 해도 믿지 말고 직접 돌려본다.

**3. 단계가 끝나면 커밋하고 대화를 새로 시작한다.** 대화가 길어질수록 앞부분 규칙을 잊는다.

**4. 도구 선택**

| 상황                            | 도구        |
| ------------------------------- | ----------- |
| 파일 여러 개를 새로 만드는 작업 | 클로드 코드 |
| 기존 파일 한두 개 수정          | 커서        |
| 오류 원인 추적                  | 클로드 코드 |
| 화면 세부 조정                  | 커서        |

**5. 프롬프트에 항상 들어가야 하는 세 가지**

- 무엇을 만들지 (한 문장)
- 어떤 문서를 먼저 읽을지
- 끝났는지 판단하는 기준

# 1단계 · 인프라 관통 (P1~P3)

> 목표: 화면이 비어 있어도 좋다. **클라우드 DB에 붙고 배포 주소가 열리는 것**까지.
> 이 단계를 건너뛰고 화면부터 만들면 나중에 배포가 막혀 전부 날아간다.

## P1. 프로젝트 초기화

```
Next.js 15 App Router + TypeScript(strict) + Tailwind로 새 프로젝트를 초기화해줘.

요구사항:
- 패키지 매니저는 pnpm
- ESLint + Prettier + lint-staged + husky 설정 (커밋 전 타입체크와 린트 실행)
- 폴더 구조: app/, components/, lib/, harness/, docs/
- .env.example 파일에 앞으로 필요할 환경변수 이름만 미리 적어둘 것
  (오라클 접속 정보, 지갑 경로, 인증 시크릿)
- .gitignore에 .env와 지갑 파일 추가. harness/results는 커밋하므로 제외하지 말 것

절대 하지 말 것: Prisma 설치, Vercel 관련 설정 추가

끝나면 pnpm dev로 기본 화면이 뜨는지 확인할 수 있게 알려줘.
```

**확인** — `pnpm dev`로 화면이 뜬다. `pnpm build`가 통과한다.

---

## P2. 오라클 연결

```
node-oracledb Thin 모드로 오라클에 접속하는 DB 연결 모듈을 만들어줘.
.cursor/rules/oracle.mdc의 규칙을 먼저 읽고 따라줘.

요구사항:
- lib/db/pool.ts: 커넥션 풀을 앱 시작 시 1회만 생성하고 전역 캐싱
  (Next.js 개발 모드에서 매번 재생성되지 않게)
- lib/db/query.ts: 바인드 변수만 받는 조회/실행 헬퍼. 커넥션은 finally에서 반환
- 접속 정보는 전부 환경변수. 로컬 접속과 클라우드(지갑) 접속을 환경변수만 바꿔 전환할 수 있게
- app/api/health/route.ts: DB에 SELECT 1을 던져 연결 상태와 응답 시간을 반환

연결 실패 시 어떤 에러 메시지가 나오는지도 확인할 수 있게 처리해줘.
```

**확인** — 로컬 오라클로 `/api/health`가 정상 응답. 그다음 환경변수만 클라우드로 바꿔서 또 정상 응답.

## P3. 배포 관통

```
이 프로젝트를 상시 구동형 호스팅에 배포하려고 한다.
Vercel은 서버리스라 오라클 커넥션 풀을 유지할 수 없어서 쓰지 않는다.

- Dockerfile과 실행 스크립트를 만들어줘 (Node 22 기준, 멀티스테이지 빌드)
- 오라클 지갑 파일을 이미지에 넣지 않고 실행 시 마운트/환경변수로 주입하는 방식으로
- 배포 후 /api/health로 헬스체크가 가능하게
- README에 배포 절차를 단계별로 적어줘
```

**확인** — 배포된 주소에서 `/api/health`가 클라우드 DB 응답을 돌려준다. **1단계는 여기까지다. 화면이 비어 있어도 이게 끝나면 성공이다.**

## P14. 전이 함수와 훅

```

## P15. 재고 할당 프로시저

```
재고 할당을 처리하는 PL/SQL 프로시저를 만들어줘.
.cursor/rules/oracle.mdc의 트랜잭션·잠금 규칙을 반드시 따를 것.

요구사항:
- 주문 하나의 모든 상품에 대해 재고를 할당
- 대상 행은 PRODUCT_ID 오름차순으로 SELECT ... FOR UPDATE WAIT 3
- 조건부 갱신으로 이중 방어 (가용재고 >= 요청수량일 때만 반영)
- 하나라도 부족하면 전체 롤백하고 BACKORDER 처리 (부분 할당 안 함)
- 성공 시 INVENTORY_TRANSACTIONS에 기록
- 결과를 OUT 파라미터로 반환 (성공/부족 상품 목록)

애플리케이션 코드에서 재고를 계산해 넣는 방식은 금지.

# 프롬프트 작성 원칙 (직접 쓸 때)

1. **"만들어줘"만 쓰지 말고 "어디를 읽고" "무엇을 지키고" "어떻게 확인할지"를 함께 준다**
2. **금지 사항을 명시한다.** AI는 "하지 마라"에 더 잘 반응한다
3. **큰 작업은 쪼개서 단계마다 확인받게 한다.** 한 번에 다 만들면 검토가 불가능하다
4. **"추측하지 말고 파일을 먼저 읽어줘"를 습관처럼 붙인다**
5. **수치가 걸린 작업은 "측정 결과를 함께 제시해줘"를 붙인다**
6. **결과가 이상하면 프롬프트를 고쳐서 새로 시작한다.** 같은 대화에서 계속 고쳐달라고 하면 점점 나빠진다
